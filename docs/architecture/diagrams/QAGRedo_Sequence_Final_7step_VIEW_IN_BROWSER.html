QAGRedo — processing sequence (7 steps)

Browser-friendly version of the 7-step sequence diagram.

What the step colors mean

  • Blue (steps 1, 6) — Runner ↔ Workflow Engine: start the job and return the final decision.
  • Green (steps 2, 3) — Calls to the generator model (Ollama or vLLM, by profile).
  • Orange (steps 4, 5) — Independent judge-model path for grounding/quality checks.
  • Purple (step 7) — Save verified outputs and run summary to Artifacts.
Tip: Use this HTML view in Cursor/VSCode preview or a browser for quickest inspection.
Maintainer index: docs/HANDOVER.md
Profiles: QAGREDO_PROFILE=vllm (default, dual GPU), ollama (host Ollama), or kubeflow (in-container Ollama). Config files: config/config.ollama.yaml, config.kubeflow.yaml, config.vllm.yaml.
Resume partial runs: bash run.sh -- --resume skips documents that already have *_analysis.json and reuses the latest run folder under output/.
Post-run split: bash run.sh --minimise writes per-document split files; --minimise-good / --minimise-bad are split-only shortcuts *_analysis_minimal_good_pairs.json and *_analysis_minimal_bad_pairs.json.
Offline deployment: Keep qagredo_bundle.tar.gz and qagredo-v1.tar aligned with requirements.txt. After docker load, run bash verify_offline_deployment.sh in qagredo_host/. Details: docs/OFFLINE_SETUP_GUIDE.md.
