QAGRedo — management overview

One-page summary for stakeholders: what the system does, how it runs, and what you get out. Technical detail is in the engineering diagrams pack.

What it does

  • Reads prepared documents (JSON/JSONL).
  • Uses AI to draft questions and answers grounded in each document.
  • Checks quality (grounding / confidence) and saves a structured analysis file per document.

End-to-end flow (simplified)

flowchart TB
  doc[Documents_in] --> qlist[AI_question_list_per_document]
  qlist --> slot[Each_slot_write_answer]
  slot --> qc[Quality_check]
  qc --> gate{Good_enough}
  gate -->|no| repl[Replacement_question_same_slot]
  repl --> slot
  gate -->|yes| more{More_slots}
  more -->|yes| slot
  more -->|no| save[Save_analysis_JSON]
  save --> gh[Publish_to_GitHub]

Questions first: the pipeline asks the AI for a batch of questions for each document (count is configured). Then for each slot it generates an answer. If the quality check fails, it can draft a replacement question for that same slot and try answers again (within limits), not only re-answering the same question text.

How it runs (typical offline setup)

flowchart TB
  subgraph stack [Three_parts]
    G[AI_A_questions_and_answers]
    J[AI_B_independent_checker]
    R[Pipeline_CPU]
  end
  R --> G
  R --> J

Why two AIs? The same model should not both write and judge the answer; a second model improves trust in the quality signal. The default grading path is the independent LLM judge (legacy semantic / hybrid labels are compatibility-only, without embedding-model loading).

Runtime profiles

  • vllm (default) — Two GPU services (generator + judge); edit config/config.vllm.yaml.
  • ollama — Ollama on the host; edit config/config.ollama.yaml.
  • kubeflow — Ollama inside one container; edit config/config.kubeflow.yaml.

Set QAGREDO_PROFILE in .env (ollama | kubeflow | vllm) — required.

Resume a partial run

Skip documents that already have *_analysis.json in a prior run folder. Use bash run.sh --pipeline-only --resume (vLLM) or bash run.sh -- --resume (ollama/kubeflow). See OFFLINE_SETUP_GUIDE.md §8.

Deliverable

  • Timestamped output folder with one analysis JSON per document (full detail by default).
  • Post-run bash run.sh --minimise writes *_analysis_minimal.json plus per-document *_analysis_minimal_good_pairs.json and *_analysis_minimal_bad_pairs.json (no LLM rerun).
  • During a run, bash run.sh -- --minimal-qa-output saves slim *_analysis.json directly — different from --minimise.
  • bash run.sh --summarize --latest --json builds run_summary.json for the run folder.
  • Failed slots are kept in full *_analysis.json for bad-pair export unless config omits them.
